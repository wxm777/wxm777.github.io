AI辅助渗透工作流的设计：AI-SRC工作目录详解

发表于 2026-09-12 分类于 方法论 本文字数： 6.5k 阅读时长 ≈ 6 分钟

0x00 前言

把 AI 用在渗透测试上，试过的人大多会踩到同样的坑：它很会写 payload，但没有纪律（上来就对着目标狂轰滥炸）、没有记忆（每次会话从零开始，上周踩过的坑这周再踩一遍）、没有边界（不知道什么能测什么不能测，也不知道什么时候该停）。

我的解决方案是把这些约束全部固化到一个工作目录里，让 AI 在这个目录里按既定规则工作——方法论写在配置里，经验沉淀在知识库里，进度落盘在工作区里，红线钉死在合规文件里。这套系统叫 AI-SRC，跑在 Claude Code 上，目前已在教育 SRC 和公司授权测试两类真实任务中使用。

这篇文章把整套工作目录拆开讲清楚：为什么这么设计、每个目录干什么、规则怎么约束 AI。

0x01 全局架构：五层分工

整套系统的方法论骨架是五层架构，写在根目录的 CLAUDE.md 里：

设计要点有三个：

  1. 成本分层：S1 便宜，可以广撒网；S3 贵，必须等 S2 排好优先级再投入。AI 最容易犯的错就是不分轻重全程高成本乱撞，分层就是治这个的。
  2. 开场强制序列：收到目标后必须按序执行——建工作区 → S1 固定流程（人工走站、指纹识别、接口提取、结果判读）→ 向人简报结论——之后才能进入 S2/S3。未完成信息收集前，禁止任何漏洞测试动作，连秒杀卡都不许打。这条是为了防止 AI 看到登录框就直接开始注。
  3. 假设驱动而不是 payload 驱动：S2 的产出是排好优先级的假设清单（P0 立即验证 / P1 批量测试 / P2 记录备忘），每个 P0/P1 必须能预答”利用方法 + 能拿到什么”，答不出不立项。AI 不能”顺手试试”，只能”验证假设”。

0x02 目录结构总览

双模式设计：edusrc/ 和 pentest/ 是两个工作模式，各有自己的规则文件。这个设计直接利用了 Claude Code 的加载机制——在 edusrc/ 目录启动会话时，Claude Code 会同时加载父目录的 CLAUDE.md 和当前目录的 CLAUDE.md，即”通用底座 + 模式规则”两层自动叠加；共享资源（知识库、工具、记忆）只有一份，模式规则只写差异。规则叠加而不是复制，方法论改一处两边生效。

早期我在另一个 agent 平台上也维护过一份同源实现，两套规则文本同步的成本很高，九月起全部收敛到 Claude Code 这一套，只维护一份。

0x03 工作区：一切产物落盘

每个测试目标一个独立工作区，命名 workspaces/YYYY-MM-DD-目标名/，内部结构固定：

几条强制纪律：

  • 开测第一步就是建这个文件夹，之后所有笔记和证据只写进这里，任何文件不得散落在根目录；
  • findings.md 无论有没有挖到洞都要写，没挖到也要记录验证范围和未测项，收工时不得为空；
  • 每验证一个漏洞立刻写进 report.md，必须含完整请求/响应包和可复现 Payload，不允许”先记着回头补”；
  • 大量原始抓包存 evidence/，findings.md 只放提炼后的关键包，防止文件膨胀到没法读。

收工后工作区归档到 workspaces/_done/，同时在 report/README.md 总索引里登记一行：目标、漏洞数、高中低危分布、收工原因。零发现的目标也要登记收工原因——比如”三接口参数化 + 雷池全拦，无洞”、”验证码闸门有效，注入点不可达”。九月上旬教育 SRC 实测的 18 个目标里，只有两个出了高危，但其余 16 个的收工原因同样有价值：下次遇到同类系统，先看索引就知道哪些路已经趟过、死在哪儿，不重复投入。

0x04 知识库三层：让经验按使用频率分层

分层的逻辑是加载成本：AI 的上下文是稀缺资源，不能把所有知识一次性塞进去。S1 阶段只需要快速判据，秒杀卡限制 50 行以内；S2/S3 需要验证路径，决策树给到 100 行；深度绕过手法最多最杂，做成按需加载的 techniques，卡壳时才读对应那一篇。

两个配套机制：

  • quick-ref 的索引是决策表：_index.md 里不是文件列表，而是”S1 发现 → 加载哪张卡 → 打什么动作”的映射，比如”参数含 id/user/uid → idor 卡”、”参数值在响应中回显 → xss 卡”、”参数含 search/query → sqli 卡”。索引同时写明使用限定：卡片只在流程走到对应阶段时加载，禁止拿到目标逐项测试。
  • skills 按需生长，不预写教科书：索引里规划了十几类漏洞的决策树，但实际只创建了 3 个——idor、sql-injection、getshell，都是实战踩过坑之后才沉淀的。规则写明了”skill 文件不存在时直接按模型能力测试，不受阻”，知识库随实战自然生长，而不是先抄一遍教科书。

内容上只沉淀三样东西：实战踩坑的对策、从文章里学到的新手法、防遗漏检查清单。比如 skills/sql-injection.md 里没有”什么是 SQL 注入”，只有”前置条件 → 快速判定表 → 各数据库的绕过分支 → 防遗漏项”。

0x05 记忆系统：骨架、自我认知、反馈规则

这是整个系统里我觉得最有价值的部分，目前有三个产物。

骨架库（memory/skeletons/）：把每类系统的攻击面模式抽象成模板——框架指纹、常见接口、数据模型、鉴权模式、典型攻击链、开发者犯错模式，再打行业标签。目前积累了 7 个，比如：

教育系统 com.seaz + Acegi 老栈（高置信度，实战来源）：ECCustom 自定义 JSP 双编码注入 / 运算符优先级闭合免注释符 / ServiceAction 反射分发 / File 组件未授权上传面

下次再遇到同栈系统，S2 阶段直接匹配骨架，历史攻击链立刻变成新目标的假设候选。骨架按置信度分级：实战验证 = 高，可直接套用；文章学习 = 低，仅作参考。总数限制 20 个以内，防止无限膨胀变成噪音。

自我认知（memory/self-awareness.md）：AI 统计自己的命中率和优劣势，分三块——命中率表（按漏洞类型计数，统计口径写明”按实际执行了判定的假设计数，非按目标数”，没有完整分母不编造命中率）；优势模式（实战中验证过的可复用攻击链，比如”WAF 精确拦函数名就逐函数探测找漏网等价函数”、”渲染通道外带”）；已知盲区（比如”雷池语义引擎对新部署无有效绕过手段，遇到先判参数化而不是投入绕过研究”）。这份文件的作用是让 AI 对自身能力边界有量化记录，减少没有依据的高估。

反馈规则（memory/feedback-rules.md）：把人纠正过的行为固化成跨会话规则。比如”工具或 MCP 调用失败时立即汇报原始错误并暂停，不许用替代工具默默绕路”、”浏览器环境准备是 AI 的职责，不要列成用户的手工步骤”。每条都附来源（哪次任务、什么原因被纠正）。AI 被纠正一次是对话级记忆，写进这个文件才是系统级修复。

三个约定命令贯穿其中：

  • /me：进度落盘，把当前任务状态写完再走；
  • /rem：完整复盘，增量更新四个产物（秒杀卡 / 决策树 / 骨架 / 自我认知），并检查重复冲突——相同来源更新原条目，不追加重复经验；
  • /stu <url>：学习一篇文章，提取新 payload / 攻击链 / 骨架写入知识库。

0x06 合规与边界：红线是配置，不是口号

AI 做渗透，最不能妥协的是边界。这套系统把边界写成了三层可执行的配置：

第一层，通用底线（根底座，所有模式不可突破）：最小必要原则；凭据类数据（口令哈希/密钥/token）任何情况下不读取不提取；植入后门、删除操作、影响真实用户、大规模拖库绝对禁止；写入操作必须先经人确认。

第二层，模式收紧。两个模式的收紧方向完全不同，这恰好体现了分层的好处：

  • edusrc：禁用一切主动扫描器（tools/scanner/ 下 nuclei/afrog/xray/fscan 等一律锁死，只允许 tools/recon/ 只读探测）；SQL 注入只允许只读深入验证；目标归属存疑先问人再动手。
  • pentest：开工前必须把授权信息落盘成 scope.md（授权时间窗、目标清单、允许动作、白名单状态、禁止动作），信息不全不允许开测；任何超出 scope 的动作一律先问人。扫描器在这个模式放开，但有独立的 S1.5 调度层：限速、时间窗、白名单确认是每次扫描前必过的前提检查，且扫描命中绝不直接进报告——全部进”待复核清单”，人工重现确认后才算数，误报也记录（防重复复核）。

第三层，价值过滤，同样按模式分化：edusrc 按 SRC 平台收录规则过滤，平台明确忽略的类型（Self-XSS、无敏感 CSRF、纯 DoS 等）直接淘汰不测，注入类必须能预答”实际能取出什么数据”，答不出不立项；pentest 反过来要求低危全覆盖——信息泄露、配置错误这些 SRC 忽略类，客户报告需要，一项不许丢，配套有专门的低危检测清单逐项过。

还有一条行为规范贯穿始终：工具失败立即汇报，不用替代工具默默绕路；遇到需要人工的环节（验证码、登录确认）立即暂停等人。AI 的”自主性”被严格限制在执行层，所有涉及判断和边界的节点都回到人手里。

0x07 工具链：全部 CLI，索引进 tools/README.md

tools/ 按职责分组：recon/（只读探测，httpx/P1finger/URLFinder/dirsearch/wafw00f 等）、scanner/（主动扫描，仅 pentest 模式可用）、exploit/（定向利用，ysoserial/shiro/weblogic/fastjson 等，指纹命中才触发）、dict/（字典库，按 web/子域名/参数名/口令分类）。

tools/README.md 是总索引：每个工具的调用命令、输出格式、适用场景、注意事项都写死，AI 先查索引再调用，不许猜参数。几个关键约定：

  • recon 与 scanner 物理分开：edusrc 模式下 scanner 整个目录禁用，从目录结构上隔离越权可能，不靠自觉；
  • 高价值指纹必须交叉确认：Shiro、Struts2 这类带 N-Day 的组件，单个指纹工具的规则匹配可能误报，要求多个指纹工具结果一致才写入世界模型——单工具误报不进入决策链；
  • GUI 工具禁止拆解改造：没有 CLI 覆盖的组件（struts2/thinkphp/若依/OA 综合等），主动提醒用户去本地工具箱手动跑对应 GUI 工具，不沉默跳过、不自造轮子；
  • 浏览器与 Burp 是固定环境：浏览器控制走 Playwright MCP 桥模式（Chrome 扩展直连真实浏览器，复用登录态），Burp MCP 负责抓包重放，配置固定在 .mcp.json 里。任务开始时 AI 自动完成环境准备（带代理参数重启 Chrome、验证 MCP 连通），这不是用户的手工步骤。

0x08 实战效果

这套系统九月上旬在教育 SRC 跑了 18 个目标，产出两个高危链：一个 SQL 注入拖取 1.4 万条新生信息（双 URL 编码绕过全局过滤器），一个 API 网关多实例鉴权不一致泄露 5.2 万条学生信息并升级为账号接管——每个漏洞从 S1 信号、S2 假设、S3 验证记录到报告归档，整条链在对应工作区里完整留痕。这两个案例加上一个未授权文件上传，都已在前面的复盘文章里单独写过（另两篇：文件上传、网关鉴权不一致）。

pentest 模式也在九月上旬的一次企业内网授权测试中实际跑过一遍：scope.md 落盘、S1.5 扫描器调度、低危清单逐项覆盖、按模板出客户报告，流程完整走通。

值得一提的是零发现目标的价值：18 个教育 SRC 目标里 16 个无洞，但每个都沉淀了东西——“雷池全拦时的缺参 500 证伪法”、”函数白名单注入防护的识别特征”、”瑞数类 WAF 下大字典扫描会封 IP”。这些进了骨架库和自我认知，下一次同类目标的 S2 直接受益。无洞不等于无产出，这是这套落盘纪律带来的复利。

0x09 总结

这套工作目录解决的三个问题，回头看对应三个设计决策：

  1. 纪律 → 分层架构 + 假设驱动 + 开场强制序列：AI 不能乱来，信息收集没做完不许测漏洞，每个测试动作挂在排好优先级的假设上；
  2. 记忆 → 工作区落盘 + 骨架库 + 自我认知 + 反馈规则：每次会话从落盘文件恢复现场，经验和教训以结构化形式跨会话复用；
  3. 边界 → 三层合规配置 + 工具目录物理隔离 + 失败即停汇报：红线写在 AI 必读的配置里，而不是指望它自觉。

AI 在渗透里的价值不是”更快的扫描器”，而是一个可以被工程化约束的执行者——给它方法论、记忆和边界，它负责执行和记录证据链。这套工作目录就是这些约束的载体。

方法论上借鉴了 PentestGPT（假设任务树与上下文续接）、pentest-ai-agents（验证职责与证据记录）和 Shannon（候选去重与验证后入报告）的思路，本地实现未引入它们的执行器，有兴趣可以对比阅读。

本工作流仅用于授权目标（SRC 平台规则或书面授权），所有红线配置以”模式规则可收紧不可突破”为原则。
